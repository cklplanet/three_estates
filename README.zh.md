# Three Estates

**简体中文** | [English](README.md)

Three Estates 是一款由终端驱动的社交推理模拟器。由 LLM 驱动的角色会在不同桌位之间移动、交谈、展示信息、使用角色能力、形成长期记忆，并分别追求自己的胜利条件。

模拟器支持 10 人基础规则和 16 人扩展规则。每个智能体都只能依据有限信息行动：它知道自己的角色与经历，能感知当前桌位的活动，只有当远处的说话声足够大时才能听见。系统会把检索出的记忆、人物关系、当前局势和各桌倒计时组合进每次决策提示中。

> **项目状态：** 正在积极开发的实验性项目。完整运行一局会调用大量外部 LLM API，可能产生较明显的费用。

## 主要特点

- 最多 **16 个自主智能体**，各自拥有角色、能力、家族与独立胜利条件。
- 基于句向量、联想记忆、时近性/相关性评分与自动反思的 **RAG 辅助记忆**。
- 根据座位、移动、音量和事件现场人员实现的 **局部可观测性**。
- 完整自动化的离席、行动竞价、抵达、亮牌、能力结算、桌位封锁与终局计分流程。
- 通过可复用人物资料、方向性关系、本局专用上下文与历局总结存档维持人物连续性。
- 稳定的游戏检查点、阶段快照与角色生成分步检查点，可在中断后继续。
- 角色生成会先根据初始背景一次性确定完整姓名名单，再依照固定名单逐一生成资料；背景中明确列出的角色会被优先严格保留。
- 三种对话风格：策略、由休闲转为策略，以及全程超休闲。
- 人物生成、游戏推理、对白、记忆重要度评分和赛后写作可分别配置模型。
- 完整日志、纯对白日志、按桌/按人物日志、赛后总结与视觉小说式尾声。
- 可复用的本地化系统；目前提供英文、简体中文与日文。

## 一局游戏如何运行

角色起始于城堡、森林、村庄；扩展规则另有荒野。每个模拟时间步依次进行：

1. 智能体决定留在当前桌位还是离席。
2. 符合条件的行为通过内部竞价系统竞争执行机会。
3. 被选中的对白、亮牌、角色能力与即时反应依序结算。
4. 途中角色抵达目的地，并感知其有资格听见的对话。
5. 在下一阶段开始前更新记忆与反思。

每张主要桌位都有独立截止时间。倒计时结束后，桌上角色将无法离席。智能体必须在终局前平衡交谈、收集信息、欺骗、移动和角色专属目标。

## 游戏设计目的

Three Estates 并非围绕两个固定阵营或单一共同胜利条件设计。每名角色都会被单独判定胜负，不同目标只会部分重合，因此游戏鼓励：

- **临时联盟：** 角色可以协调移动、交换信息、相互保护，或共同安排对双方都有利的终局桌位。
- **跨家族合作：** 同一家族不代表目标一致，不同家族之间反而可能互惠。
- **谈判与交易：** 角色可以交换真信息、承诺、保护、牌权或站位协助。
- **欺骗与背叛：** 含糊声称、选择性真话、虚假结盟与最后一刻离席都可能是合理策略。
- **信息不对称：** 对话以桌位为局部范围，远处声音只会有限传播，记忆仅包含角色本人能感知的事情。
- **动态利益：** 牌被偷走或转交、角色互换、倒计时封锁和公开信息都会改变联盟价值。

贵族、神职人员和平民三个家族用于组织能力与部分推理线索，但不是固定队伍。终局时，每名玩家按照自己当时的个人角色独立判定胜负。

## 角色、能力与胜利条件

10 人基础游戏中，每种角色恰好一名。玩家的**角色**、**家族**和**胜利条件**与其角色牌的物理位置并不相同：失去牌可能使玩家无法亮牌或发动能力，却不会自动改变其角色身份。成功的盗贼互换是角色与胜利条件真正交换的主要方式。

| 角色 | 家族 | 能力 | 胜利条件 |
| --- | --- | --- | --- |
| **国王（King）** | 贵族 | 在桌边时选择一个当前在场的家族。该家族中宣告时已经在桌边的玩家不能离席，直到国王或另一名未受影响的玩家离开。国王封锁贵族时仍可自行离开，但离开会解除封锁。 | 城堡中的平民不超过一人。 |
| **王后（Queen）** | 贵族 | 离席时可指定另一名玩家跟随至同一目的地；该玩家会被留在那里，直到王后或另一名玩家离席。免疫或更强的封锁可能阻止拖行。 | 终局时位于城堡且同桌没有国王，或位于村庄且同桌至少有一名神父。其他角色手中的国王/神父散牌不算对应角色在场。 |
| **男爵（Baron）** | 贵族 | 在至少三人的桌上，当其他玩家展示自己的角色牌时，可以亮出男爵牌，阻止相关能力并偷走已展示的牌。若只是自愿亮牌，公开信息仍成立，但牌仍可被偷。男爵不会获得被偷角色及其能力。 | 持有至少三张不含自己男爵牌的牌；自愿获赠的修女牌也计入。 |
| **主教（Bishop）** | 神职人员 | 其他玩家离席后，可猜测一名仍在桌边玩家的家族。猜对会强制目标立即离席；猜错时目标可自行决定回应中透露多少信息。 | 最终桌位上没有贵族。 |
| **神父（Priest）** | 神职人员 | 与恰好另一人单独同桌时，可查看对方角色；若目标已不持有自己的角色牌，尝试失败。 | 森林中的总人数不超过一人。 |
| **修女（Nun）** | 神职人员 | 与恰好另一人单独同桌时，可把修女牌交给对方。持牌者在归还前免受大多数敌对能力影响，并且必须在该修女要求时归还其牌。 | 至少三名平民获胜。 |
| **纺纱女（Spinster）** | 平民 | 离开森林时可指定一名仍在森林的玩家；纺纱女离开后，该玩家必须向森林中其余所有人公开角色。 | 终局时猜测最终同桌的所有其他角色；若全部猜对，则该桌其他玩家的胜负结果全部逆转。 |
| **农民（Farmer）** | 平民 | 免疫大多数其他角色能力。例外包括接受修女保护、神父或纺纱女造成的直接公开，以及纺纱女的终局逆转。需要证明免疫时可以展示农民牌。 | 最终同桌至少有两名神职人员。 |
| **盗贼（Thief）** | 平民 | 与恰好另一人单独同桌时，可交换双方角色与胜利条件。目标若不持有自己的角色牌则失败；盗贼不能以盗贼为目标；桌面状态未变化前，同一对玩家不能立刻反向交换。 | 村庄里所有非盗贼玩家都落败，或不存在非盗贼玩家。 |
| **旅店老板（Innkeeper）** | 平民 | 从其他桌位进入村庄时，可亮牌并宣告旅店老板。发动后，直到旅店老板离开或另一名玩家进入前，任何人都不能离开村庄。仅仅从村庄开局或一直留在村庄不会发动。 | 最终同桌至少有两名贵族。 |

### 16 人扩展规则

扩展模式加入荒野作为第四张桌位，并采用以下角色数量：

| 角色 | 数量 | 扩展模式变化 |
| --- | ---: | --- |
| 国王、王后、纺纱女、主教、旅店老板 | 各 1 | 能力与基础模式门槛不变 |
| 神父 | 2 | 能力与胜利条件不变 |
| 修女 | 2 | 保护可叠加；持有至少一张自愿获赠的修女牌时仍受保护。每名修女需要至少五名平民获胜。 |
| 农民 | 3 | 每名农民的最终桌位都需要至少三名神职人员。 |
| 盗贼 | 2 | 盗贼仍免疫盗贼互换。 |
| 男爵 | 2 | 男爵可以阻止另一名符合条件的男爵，并偷走其累积的战利品牌，但永远不能偷走对方自己的男爵牌。每名男爵需要至少四张战利品牌。 |

荒野不会直接出现在任何胜利条件中；它用于在主要桌位关闭前创造额外路线、谈判和临时联盟空间。

## 环境要求

- Python 3.9 或更高版本
- [OpenRouter](https://openrouter.ai/) API 密钥
- 首次运行时可访问互联网，以下载 `all-MiniLM-L6-v2` 句向量模型
- OpenRouter 账户能够访问环境配置中填写的模型

## 快速开始

克隆仓库并创建虚拟环境：

```bash
git clone https://github.com/cklplanet/three_estates.git
cd three_estates
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

创建本地配置：

```bash
cp .env.example .env.local
```

至少填写：

```dotenv
OPENROUTER_KEY=YOUR_API_KEY_HERE
THREE_ESTATES_SESSION_NAME=my_first_game
THREE_ESTATES_LOCALE=zh-CN
```

检查同一文件中的模型 ID，并替换为你的 OpenRouter 账户可用的模型。随后从仓库根目录启动：

```bash
python3 three_estates_sim/server.py
```

终端会依次引导你选择游戏人数、角色生成方式、对话风格、外貌/上下文、人物关系及初始座位。现有存档可以继续，也可以保留人物并沿用角色、重抽角色、完全复现初始配置，或归档后生成全新角色组。

## 配置

程序优先读取普通环境变量，然后读取 `.env.local` 与 `.env`。完整示例见 [`.env.example`](.env.example)。

| 变量 | 用途 |
| --- | --- |
| `OPENROUTER_KEY` | LLM 请求使用的 API 密钥 |
| `THREE_ESTATES_SESSION_NAME` | `three_estates_sim/sessions/` 下的存档目录名 |
| `THREE_ESTATES_SESSION_DIR` | 可选的绝对存档路径，用于覆盖目录名 |
| `THREE_ESTATES_LOCALE` | 界面及生成语言：`en-US`、`zh-CN` 或 `ja-JP`（实验版；需校正） |
| `THREE_ESTATES_GAME_MODE` | 默认规则：`10` 或 `16` |
| `THREE_ESTATES_CHARACTER_MODEL` | 角色资料与人物组生成 |
| `THREE_ESTATES_GAME_MODEL` | 移动、竞价、能力与策略推理 |
| `THREE_ESTATES_DIALOGUE_MODEL` | 对白、动作与表情生成 |
| `THREE_ESTATES_SPINSTER_GUESS_MODEL` | 纺纱女终局猜测；未设置时沿用对白模型 |
| `THREE_ESTATES_POIGNANCY_MODEL` | LLM 记忆重要度评分 |
| `THREE_ESTATES_EPILOGUE_MODEL` | 赛后总结与尾声 |
| `THREE_ESTATES_SECONDS_PER_PHASE` | 普通策略阶段推进的模拟秒数 |
| `THREE_ESTATES_CASUAL_SECONDS_PER_PHASE` | 休闲阶段推进的模拟秒数 |
| `THREE_ESTATES_USE_LLM_CHAT_POIGNANCY_SCORING` | 是否在策略阶段启用 LLM 评分；休闲对话默认启用 |
| `THREE_ESTATES_ALLOW_SPEECH_REASONING` | 是否允许对白模型使用默认推理模式 |

## 本地化系统

设置 `THREE_ESTATES_LOCALE=zh-CN` 可启用简体中文，设置为 `ja-JP` 可启用日文终端界面和日文生成内容。本地化包位于：

```text
three_estates_sim/backend_server/locales/<locale>/
├── strings.json
└── prompts/
```

- `strings.json` 保存终端提示、消息与显示名称。
- `prompts/` 可按原英文模板的同名文件提供局部覆盖。
- 某项翻译缺失时会先回退到 `en-US`，提示模板最终回退到原始英文文件。
- 所有提示都会附加当前语言的输出约束，因此不需要一次翻译全部策略提示。

内部协议标识始终使用规范英文，包括存档 JSON 键名、角色/家族/桌位 ID、结构化输出枚举值。这使同一存档可以在不同显示语言间切换，也避免本地化破坏规则判断。

要添加新语言，只需复制一个现有语言目录，翻译所需字符串或提示文件，再把 `THREE_ESTATES_LOCALE` 设置为新目录名。无需复制模拟器代码，也无需从第一天起翻译所有提示。

## 存档与输出

默认存档位置：

```text
three_estates_sim/sessions/<THREE_ESTATES_SESSION_NAME>/
```

其中可能包括人物 scratch 状态、联想记忆、`character_context.json`、`session_state.json`、不可变阶段快照、多种对白/调试日志及赛后尾声。存档目录和 `.env.local` 默认被 Git 忽略，因为其中可能含有私人提示、生成内容和凭据。

## 设计说明

- 模拟以智能体个人视角为中心，而非全知视角；记忆只记录角色有机会感知的内容。
- 对白生成返回结构化的语言、表情和身体动作字段。
- 各类模型可以独立调优，以平衡质量、延迟与成本。
- 历局总结会保留存档以供参考，但不会自动膨胀后续运行时提示。
- 角色生成和阶段检查点采用原子写入，中断后可以从已完成步骤恢复。
